## 🖼️ Fotos da Caixa no e-mail — causa-raiz encontrada e resolvida (self-hosting)

**Sintoma:** a foto de imóveis da Caixa quebrava no e-mail, mesmo com a URL certa.

**Diagnóstico definitivo** (workflow `diag-fotos-bd` no imóvel de Feira de Santana `F855552686059921.jpg`):
| Origem da requisição | Resultado |
|---|---|
| Caixa **direto**, IP de datacenter (GitHub Actions/Azure) + Referer | ✅ `200 image/jpeg 65KB` |
| Nosso **img-proxy edge** (Cloudflare) | ❌ `404` |
| Nosso **img-proxy node** (AWS us-east-1) | ❌ `404` |
| Bright Data unlocker (binário) | ⚠️ `200` porém **0 bytes** |

➡️ **A Caixa RECUSA os IPs da Vercel (edge E node) e só atende datacenters como o do GitHub
Actions.** Nenhum proxy hospedado na Vercel resolve. O padrão de URL correto é `F<num>21.jpg`
(o `F<num>.jpg` dá 404) — isso estava certo; o problema era o IP do proxy.

**Solução — self-hosting no Supabase Storage** (PR #124):
- Bucket **público** `imoveis-fotos` criado.
- `scripts/backfill-fotos-caixa.mjs`: baixa `F<num>21.jpg` da Caixa (no GitHub Actions, onde é
  aceito), sobe para `imoveis-fotos/caixa/F<num>21.jpg` e atualiza `link_foto` para a URL pública
  do Storage (CDN que o Gmail carrega direto). Idempotente/resumível; ordena por `desconto desc`
  (os atrativos, que entram no e-mail, migram primeiro).
- `.github/workflows/backfill-fotos.yml`: `workflow_dispatch` + diário **09 UTC** (após o scrape).
- `fotoParaEmail` agora **prioriza `link_foto` do Storage**; o img-proxy vira só fallback.
- `img-proxy` revertido para **edge** (o node não resolveu a Caixa; edge atende os demais hosts).

**Estado / próximo passo:** o backfill foi disparado nesta sessão para rodar a noite toda e cobrir
o pool CEF antes das 8h. **De manhã: conferir a conclusão do workflow `backfill-fotos` e reenviar o

## 📧 E-mail cron — bug de 504 em TODA execução (corrigido) — PR #122

Os logs de runtime da Vercel mostravam `504 Task timed out after 300s` em **toda** chamada do
`/api/enviar-alertas-cron` (inclusive o teste de 1 usuário). Causa: com `runtime:'nodejs'`,
`export default async function(req)` é tratado como assinatura Express `(req,res)` e o `Response`
retornado é **ignorado** → a função nunca sinaliza fim e trava até o `maxDuration`. Os e-mails até
saíam (efeito colateral), mas era frágil e queimava 300s por execução.
- **Fix:** exportar por método (`export const GET/POST = handler`) — recomendação da própria Vercel.
- **Defesa em profundidade:** `AbortSignal.timeout` em todas as chamadas de rede (PostgREST, GoTrue
  admin, Resend). Teste pós-fix: **HTTP 200 `{enviados:1,total:1}` em ~6s** (era 504).
- ⚠️ **Mesmo padrão 504 em outros crons** (não corrigidos ainda): `reconciliar-assinaturas-cron`
  (72x/3d), `laudo-retry-cron` (35x), `renovacao-avisos-cron`, `monitor-fontes-cron`,
  `limpar-documentos-cron`. Mesma correção mecânica — **candidato a um PR de limpeza**.

**Confirmações:** modo de teste (`?email=`) envia **só para o endereço informado** (filtro em
`enviar-alertas-cron` linha ~120) — os testes vão só para o admin. Agenda das 8h ativa: cron
`0 11 * * *` (11 UTC = 8h BRT), recorrente só às segundas (`isSegunda`).

**Pecini** — `web_unlocker1` (Bright Data) **confirmado**: 403 ao Puppeteer, **200 via unlocker**.
Recon fechou a estrutura:
- **Enumeração:** `GET /sitemap.xml` é um **feed de listings** (`<listing><home_listing_id>…</home_listing_id>
  <name>…</name><address><city>…<region>…<postal_code>…`) — dá TODOS os lotes em **1 request** Bright
  Data, sem JS. URL do lote = `/lote/{cidade-uf-slug}/{home_listing_id}/`.
- **Detalhe do lote** (via unlocker) tem: título, cidade/UF (slug + texto), `Avaliação: R$…`,
  `Lance Inicial/Mínimo`, `( X % de desconto)`, `og:image` (`/imagens-complete/605x487/{uuid}.jpg`),
  modalidade (Judicial/Extrajudicial/Venda direta), `Cód do leilão`, datas. Plataforma ASP.NET
  "DefaultClean" com template trimpath (`ValorMinimoLancePrimeiraPraca/SegundaPraca`, `QtdPracas` —
  útil para multi-praça).
- **Plano do scraper (amanhã):** 1) `bdFetch('/sitemap.xml')` → parse `<listing>` (id/nome/cidade/uf);
  2) para cada lote, `bdFetch('/lote/{slug}/{id}/')` → parse detalhe. **Atenção ao custo:** o Web
  Unlocker Free tem cota (≈378 usados). Se Pecini tiver centenas de lotes, o scrape diário estoura a
  cota grátis → avaliar plano pago do Bright Data OU limitar a N lotes/dia. **Decisão do dono pendente.**

## 🏘️ Filtro de bairro (pedido do dono) — estado atual + desafio

Em `Busca.jsx` o filtro de bairro **já tem**: busca-enquanto-digita (autocomplete), **multi-seleção**,
e mostra bairros **sem imóvel agora** (desde que já tenham tido lote no histórico) com "salvar para
monitorar". **O que falta** (pedido novo): listar bairros que **nunca** tiveram lote, validando via
IBGE/Correios. **Desafio real:** não há API gratuita que liste todos os bairros de um município —
o IBGE tem distritos/subdistritos (não "bairros"), e a lista completa dos Correios é o **DNE (pago)**.
Opções para amanhã: (a) dataset curado de bairros; (b) permitir bairro em texto livre para monitorar;
(c) fonte paga (Correios DNE / Google Places). **Decisão do dono pendente.**
