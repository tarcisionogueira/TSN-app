## ✅ Correções implementadas (as 3 frentes)

### 1. SSRF na raiz — `hostExternoSeguro()` (novo em `api/_allowed-hosts.js`)
A allowlist estrita `hostPermitido()` (usada em `fetch-url`/`baixar-doc`) quebraria a captura
dos endpoints de **enriquecimento** (CDNs de Sodré/Frazão/Superbid não estão na lista) — contra
a prioridade #1 do dono. Adicionado `ehHostInterno()`/`hostExternoSeguro()`: **bloqueia destinos
internos** (loopback, privados 10/192.168/172.16-31, link-local/metadados `169.254.169.254`,
CGNAT `100.64/10`, `::1`/`fe80:`/`fc/fd`, IPv4-mapeado `::ffff:`, `localhost`/`.internal`),
permitindo qualquer host público. Ligado em:
- `geocodificar-imovel.js` (`infoDoDocumento` → `link_edital`)
- `enriquecer-lote.js` (`fetchLote` → `url_lote`/`link_edital`; `lerCartorioMatricula`)
- `gerar-documental.js` (`lerDoc` → docs do banco **e** do body: `urlMatricula`/`urlEdital`/`urlRegras`)

Testado com 18 vetores de ataque + 6 hosts legítimos (CDNs de leiloeiro, CEF, IP público) → todos passam.

### 2. Scraper — mescla `anexos` em vez de sobrescrever (fix de raiz da pendência #1)
`salvarImoveis` (scraper-puppeteer.mjs) fazia `upsert onConflict:fonte_id` que reescrevia a linha
inteira → o scrape diário **apagava** os anexos/matrícula de backfill (MEGA/BIASI/Sodré em jsonb
eram transitórios). Agora, antes do upsert, carrega os docs existentes (`.in('fonte_id',…)`, blocos
de 150) e faz **união por URL** (novos = fonte da verdade do dia; agrega os de backfill que faltaram;
cap 25). Preserva `link_matricula`/`link_regras_venda` de coluna quando o scrape do dia não os traz.
**Isso torna o `backfill-docs-diario.yml` (11:30) redundante como muleta** — o backfill agora é durável.

### 3. Follow-ups de segurança
- **Gate fail-open → fail-closed** (`gerar-documental.js`): a checagem de plano (`explorador`) num
  `catch` vazio liberava a análise paga se o Supabase errasse. Agora retorna **503 retornável**
  (mesma filosofia do fix do laudo em 12/07). A cota (anti-abuso de custo) segue best-effort — o
  gate de role acima é a barreira de acesso.
- **`upload-anexo.js` — magic bytes**: valida a assinatura real do arquivo (%PDF/PNG/JPEG) além do
  content-type (forjável) — impede subir payload arbitrário (HTML/JS) como matrícula. O modelo de
  acesso (imóvel de leilão é cache compartilhado; anti-poisoning protege docs de staff) é intencional.
- **`identidade_validada` server-side** (`validar-selfie.js` + `Perfil.jsx` + migração): o cliente
  escrevia `identidade_validada=true` direto no Supabase após a IA — bastava chamar o update no
  console p/ auto-validar. Agora **/api/validar-selfie grava via service_role** (só no fluxo genérico
  selfie+doc; etapas por `tipo` do KYC de equipe não concluem identidade) e o **trigger
  `proteger_campos_sensiveis_perfil` reverte** `identidade_validada`/`_em`/`_pendente` para
  `authenticated`/`anon` não-admin (migração `20260713_proteger_identidade_validada.sql`, **aplicada**).
  Seguro: service_role e SECURITY DEFINER (`salvar_kyc_equipe`) não caem na condição do trigger.
- **Token de descadastro HMAC** (`email-alerta.js` + `cancelar-alertas.js`): `email-alerta` gerava
  `btoa('userId:unsubscribe')` — fraco **e** incompatível com o validador HMAC (link já estava
  quebrado). Agora assina no mesmo esquema (`base64url(userId).hmac16`) via WebCrypto (edge);
  paridade node↔edge testada (tokens idênticos). E `cancelar-alertas` perdeu o fallback hardcoded
  `'bidpro'` → **fail-closed** sem segredo.
